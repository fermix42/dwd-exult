CONFIRMED CAUSE AND CHANGE
The former Text_effect renderer took the actor's sprite rectangle but transformed
pos.x + TEXT_width/2 as its anchor, then subtracted half the scaled text width.
At matching scales this simply left-aligned the whole line at the actor's left
edge. Font0 was measured as one unwrapped line, with no viewport placement guard.
Different world/text scales further displaced the anchor. The diagnostic PNGs
confirmed this for both the accepted Iolo line and ordinary original NPC chatter.

The correction is in effects.cc/effects.h, shared by Game_object::say and original
Usecode item_say through Effects_manager::add_text. There is no actor ID, game/mod,
case, or dialogue-string branch in production layout. No font, palette, gump,
conversation, NPC schedule, camera-control or persistent gameplay rules change.

Text_effect::update_layout projects the speaker's actual sprite bounds to display
pixels using existing game_to_screen (including camera scroll and elevation). It
centers the measured text block over that rectangle and separates it vertically
from the sprite. If there is insufficient space above, it tries below. Final
placement is clamped inside the projected game-content rectangle, intersected with
the display, with a small margin. Letterbox space outside game content is excluded.
Contained-item rectangles are projected from gump UI coordinates, keeping those
separate from world pixels. Absolute-coordinate text remains position based.

Text_effect::wrap_lines measures candidates with the same Shape_manager font0
width API used for painting, including its horizontal leading and final glyph
ink overhang. Width is derived from the visible game area divided by the configured
text-effect scale, with padding reserved. Word boundaries are preferred; a word
that alone exceeds the available width splits by measured glyph advances. There
is no character-count wrapping rule. Newline/CRLF and the existing '~' paragraph
convention are recognized; blank lines are retained. Text/punctuation is not
rewritten. Each line is centered within the resulting block. Layout is cached
until its available logical width changes, while projected anchoring is refreshed
on every paint. Old/new display bounds are converted back to game dirty bounds.
Layer resizing, transparency, z order and cleanup continue through existing APIs.

A message taller than the viewport uses consecutive overhead pages, retaining all
lines. Each page receives the existing ten-event timeout. This extends lifetime
only for an otherwise unrepresentable multi-page message; ordinary one-page
messages, including all four accepted companion remarks, retain the original
speech-duration rule. No portrait, box, speech bubble, new input owner or keyboard
action is introduced. An extreme configured text scale is reduced only if one
glyph plus padding cannot fit; normal tested scales are preserved. Impossible
physical displays cannot guarantee subjective legibility, but content is not
silently discarded. Extremely long pages' reading pace remains a human concern;
no general speech-duration redesign is claimed or authorized by this fix.
